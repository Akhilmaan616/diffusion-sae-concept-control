Steering Stable Diffusion with sparse autoencoders

I trained sparse autoencoders on Stable Diffusion 1.5's internal activations to find features the model actually uses, then turned them up and down inside the running model. Adding one feature paints a scene in Van Gogh's style. Removing twenty doesn't take a concept away. This page lets you browse the real outputs.

The idea in three steps

Inside the model, every image position is a vector of 1,280 numbers that nobody designed. A sparse autoencoder rewrites each vector as a few "features" picked from a learned dictionary, so they can be read and edited.

1

Record

Generate 1,000 images and record one UNet layer at every denoising step: about 3.2 million vectors.

2

Decompose

Train a sparse autoencoder with 10,240 features, of which only 32 are active for any one vector.

3

Steer

During generation, add a feature to inject a concept, or switch features off to try to remove one.

Show the numbers

How it was done, briefly

  • Model: Stable Diffusion 1.5, DDIM 25 steps, guidance 7.5. Layer: the transformer block in up_blocks.1.attentions.1 (16×16 positions × 1,280 numbers).
  • SAEs: TopK (k = 32), 10,240 features; one per phase (texture, structure, composition), one pooled, and a pooled control with matched data.
  • Faithfulness: splice the SAE into the running model and measure the model's own denoising loss against clean and ablated runs.
  • Steering: edit feature codes and add the SAE's reconstruction error back, so an empty edit changes nothing. Scored with an independent CLIP model, paired by seed, 3 seeds.
  • Engineering: a 12-stage resumable pipeline that runs unattended on two free Kaggle T4 GPUs, with 28 CPU tests using a fake model.

The images here are saved outputs from those runs; this page lets you browse them and does not run the model in your browser. Limitations: one model and layer, CLIP as the judge, and the "dog", "fire" and "watercolour" features add related textures rather than the objects themselves.
